# Modbus/TCP センサーエミュレータ 要件定義書

## 1. システム概要
OT/ICSネットワーク（L2分離された ot_net）内において、物理環境のパラメーター（侵入検知、温度、水位など）をHMI（Node-RED）へ提供する仮想センサー機器をRustで開発する。
Modbusライブラリ等のブラックボックスを一切使用せず、TCPソケットのレイヤーから生のバイト列（`[u8]`）を直接パース・構築することで、プロトコルの物理的・バイナリ的構造を完全に掌握することを目的とする。

## 2. ネットワーク要件
- **プロトコル**: TCP/IPv4
- **リッスンポート**: 502（Modbus/TCP標準ポート）
- **バインドアドレス**: `0.0.0.0:502`（コンテナ起動時に指定IP `192.168.100.11` 等で待ち受け可能にする）
- **同時接続処理**: 単一のHMIからのポーリングを前提とするため、まずはシンプルなシングルスレッドのブロッキングI/O（`std::net::TcpListener`）、またはスレッドごとのコネクションハンドリングとする。

## 3. プロトコル実装要件 (Modbus/TCP)
サポートするModbusの機能コード（Function Code）は、連続値の読み取りに特化した以下1点に絞る。
- **サポート対象**: Function Code `0x04` (Read Input Registers)
  - ※機器側で計測された「読み取り専用」の連続データ（16ビット幅）を返すためのコード。

### 3.1. MBAPヘッダ（7バイト）の解析要件
受信したパケットの先頭7バイトを以下のオフセットとアライメントで正確にスライスし、検証・保持すること。
- **Offset 0-1 (2 bytes)**: Transaction ID（応答時にそのままコピーして返す）
- **Offset 2-3 (2 bytes)**: Protocol ID（Modbusの場合は常に `0x0000`）
- **Offset 4-5 (2 bytes)**: Length（以降のバイト数。応答のペイロードサイズ計算に使用）
- **Offset 6 (1 byte)**: Unit ID（スレーブID。今回は無条件で受け入れるか、特定IDのみ応答）

## 4. データ構造・バイナリ構築要件
HMIからの要求（リクエスト）に対し、正しいアライメントでレスポンスバイト列を構築し、TCPストリームへ書き出すこと。

### 4.1. データモデル（16ビットアライメント）
すべてのセンサーデータは、1つのパラメーターにつき「16ビット（2バイト）」のワード長で管理する。
- **侵入検知（今回）**:
  - 未検知 (OFF): `0x0000`
  - 検知 (ON): `0x0001`
- **将来の拡張（例：温度）**:
  - 25.5℃ (×10スケール): `0x00FF` (十進数: 255)

### 4.2. エンディアン変換（ネットワークバイトオーダ）
Modbus/TCPの仕様に則り、16ビットのレジスタデータは必ず**ビッグエンディアン**でバイト列（`[u8]`）にシリアライズすること。
- 例: 侵入検知（`0x0001`）を返す場合、メモリ上の表現から `[0x00, 0x01]` の順でバイト配列に書き込む。Rustの `.to_be_bytes()` 等を活用して明示的に変換を行う。

### 4.3. 応答パケット（PDU）の構築フォーマット
要求されたレジスタ数（$N$）に応じて、以下の構造で動的にバイト配列をアロケート・結合すること。
- **Offset 0-6**: MBAPヘッダ（リクエストのTransaction ID等を反映）
- **Offset 7**: Function Code (`0x04`)
- **Offset 8**: Byte Count ($N \times 2$ バイト)
- **Offset 9~**: Register Values（ビッグエンディアン化された $N$ 個の16ビットデータ）

## 5. 開発・実装上の制約（レッドライン）
- **既存ライブラリの禁止**: `tokio-modbus` や `rmodbus` などのModbus専用クレートの使用を厳禁とする。
- **生バイト操作の徹底**: ネットワークからのデータ受信は必ず `Read::read(&mut [u8])` 等で行い、構造体へのマッピングやパースは手動のビット演算・スライス操作によって実装すること。
- **エラーハンドリングの可視化**: 要求パケットのサイズ不足や、想定外のFunction Codeを受信した場合は、強制切断やパニックを起こさず、生バイト列の内容を標準出力（またはログ）にダンプし、解析に資する形でエラー処理を行うこと。
