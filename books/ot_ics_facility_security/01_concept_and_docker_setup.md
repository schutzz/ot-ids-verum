# 第1章：概念とシステム全体設計

---


 1. はじめに

OT/ICS（制御システム・物理セキュリティ）の通信って実際どうなってるのか気になったので、勉強用にローカルで検証環境を組んでみることにしました。

「実機を用意するのは大変なので、Dockerと各種エミュレータを使って手軽に学べるラボを作る」という目的設定でやっていきます。

そもそも「OT/ICSってなんなの？」という部分ですが、ざっくり整理すると以下の通りです。

OT（Operational Technology）：「モノ（物理機器）」を動かす・制御する技術

ICS（Industrial Control Systems）：OT環境で使われている産業用制御システム全般の総称

社会インフラ、施設管理、工場などで使われているシステムですね。

普段はITセキュリティを中心に触っていますが、OT領域のセキュリティを学ぼうとすると**「とにかくお金がかかる」**という壁にぶち当たります。実機を個人で用意するのはハードルが高すぎますし、そもそも部屋に置くスペースもありません。

そこで、「Dockerを使って物理環境をエミュレートし、ローカルで安全かつ低コストにプロトコル解析ができる環境を作ろう！」というのが本プロジェクトのスタートです。

## 2. Docker（コンテナ技術）とは何か？

「Docker（ドッカー）」とは、アプリケーションとその実行に必要な環境をセットにして**「コンテナ」**と呼ばれる独立した箱にまとめて実行・管理するオープンソースのコンテナ仮想化プラットフォームです。

### ① 従来の「仮想マシン (VM)」との違い

従来の仮想化技術（Hyper-V, VirtualBox, VMwareなど）とDockerの最も大きな違いは、**「OS（カーネル）を共有するかどうか」**にあります。

* **従来の仮想マシン (VM)**:
  * 物理ハードウェアの上にハイパーバイザを載せ、その上で「ゲストOS（UbuntuやWindowsなど）」を完全なOSとして1台ずつ起動します。
  * **デメリット**: OSをまるごと起動するため、1台動かすだけで数GBのメモリと膨大なディスク容量を消費し、起動に数分かかります。

* **Docker (コンテナ)**:
  * ホストOS（Linuxカーネル）をすべてのコンテナで共有し、CPUやメモリ、ファイルシステム、ネットワークの空間だけをLinuxの機能（`cgroups` や `namespaces`）によって**「プロセスレベルで隔離」**します。
  * **メリット**: ゲストOSが不要なため超軽量（メモリ消費は数MB〜数万KB）、かつコマンド一発・数秒で起動・停止が可能です。

![従来の仮想マシン (VM) と Docker コンテナのアーキテクチャ比較](/images/vm_vs_docker_comparison.png)

### ② なぜOT/ICSの検証環境にDockerが最適なのか？

本プロジェクトのような「施設警備システム」や「工場の制御網」をローカルPC上で安全に再現・検証する場合、Dockerには圧倒的なメリットがあります。

1. **複数機器の同時シミュレーションが可能**: 1台のPC上で「HMI監視盤」「Modbusセンサー」「BACnet門扉」「RTSPカメラ」「IDS検知器」など、10台以上の仮想機器をリソース枯渇させずに同時に動かせます。
2. **ネットワーク分離（L2ブリッジ）が容易**: Docker Composeを使うことで、現実の工場や施設と同じように「IT網」「DMZ」「OT制御網」といった隔離ネットワーク空間をコマンド一つで定義・再現できます。
3. **即座にクリーンな状態へリセット可能**: 攻撃演習やパケット改ざん実験でシステムやデータが破壊されても、コンテナを再起動するだけでわずか数秒で初期の正常状態に復元できます。

## 3. 環境の全体像（構成図）

まずどんな環境を作るのかですが、今回はイメージしやすい「施設警備システム」を模擬する形で進めます。

まずは施設警備システムを模擬する構成図です。

![施設警備システム 全体アーキテクチャ構成図](/images/ot_facility_architecture_diagram.png)

今回は、OT/ICSセキュリティの標準的なフレームワークである 「Purdueモデル（パーデューモデル）」 を参考に、Dockerの内部ネットワークを 3つのゾーン に分離して構築していく予定です。

[ ITゾーン ] ── (FW / Router) ── [ DMZ (Jump Server) ] ── (FW / Router) ── [ OTゾーン ]

 ITゾーン（業務・運用網）

役割: 一般的な社内LANや、上位の運用管理を行うゾーン。

今回の構成: Node-REDによる 統合監視盤（HMI/SCADA） を配置。

分離ポイント: OTゾーンの各種センサーやカメラと直接通信させない構造にします。

 DMZ（境界・解析網）

役割: ITゾーンとOTゾーンを仲介し、セキュリティ上の「バッファ（緩衝地帯）」となるゾーン。

今回の構成: Jump Server（踏み台・パケット解析用コンテナ） を配置。

分離ポイント:

ITからOT、OTからITへの直接の通り抜けを遮断。
この Jump Server を経由（またはここでキャプチャ）することで、OT側の生パケット（ModbusやBACnetなど）を安全に収集・解析できるようにします。

 OTゾーン（制御・物理セキュリティ網）

役割: 現場の物理機器（センサー、アクチュエータ、カメラ）が動く制御ゾーン。

今回の構成:

侵入検知センサー（Modbus/TCP）
自動ドア・ゲート（BACnet/IP）
監視カメラ（ONVIF/RTSP）

分離ポイント: 外部（IT網やインターネット）からの直接アクセスは一切不可。閉じられたローカルネットワークとして完全分離します。

 3. 各コンテナの役割と採用技術

Purdueモデルの階層意識と照らし合わせつつ、以下のようなコンテナ構成で役割分担を行います。

統合監視盤（Level 2：制御・監視層）

Node-REDを使って簡易HMI画面を作成し、全体の状態を可視化します。

物理セキュリティ機器（Level 1/0：現場機器・センサー層）

侵入検知センサー（Modbus/TCP）
自動ドア・ゲート（BACnet/IP）
監視カメラ（ONVIF/RTSP）

解析・キャプチャポイント（DMZ層）

ネットワーク境界にタップポイントを設け、`tcpdump` 等で生パケット（バイナリ）をキャプチャ・解析できるコンテナを配置します。
